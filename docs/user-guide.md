# 使用手册（dsh-onestep 1.0.0）

> 适用版本：插件 **1.0.0**；DSH 支持范围 `>=0.2.2-rc.1 <0.3.0-0 || >=0.2.1-rc.5 <0.2.2-0`；实测基线 DSH Desktop **0.2.2-rc.1**。
> 定位：给 DSH 的会话主界面加一层「1 个焦点会话 + 最多 12 个候场会话」的舞台；未进入舞台时与官方界面完全一致。
> 阅读路径：新用户读 §1–§3；日常操作查 §4–§5；出问题看 §7；原理与版本兼容见 [架构说明](architecture.md) 与 [兼容性说明](compatibility.md)。
> 相关：[README](../README.md) · [变更日志](../CHANGELOG.md) · [安全声明](../SECURITY.md) · [发布检查表](release/checklist.md) · [许可证](../LICENSE)

## 1. 能力概览

Onestep 把 DSH 的会话主区变成「焦点 + 候场」的窗口舞台：焦点会话占主位，候场会话以卡片排在左侧或顶部，拖拽即可编排，完成与待处理状态直接显示在窗口上。

| 能力 | 说明 |
|---|---|
| 1 个焦点 + 最多 12 个候场 | 默认布局仍是 1+3（最佳可读性）；上限 12，第 13 个按最久未用淘汰；候场清空自动退出舞台 |
| 候场卡静态快照 / 精简卡 | 默认静态快照（官方聊天画面渲染一次后克隆，整张按 contain 等比缩放完整显示、不裁切，随卡片大小缩放；仅状态/标题变化时重拍）；可在焦点窗「…」菜单切精简卡 |
| 自动精简降级 | 4 窗且首帧 >900ms / 主线程长任务累计 >400ms / 内存增量 >200MB 时，本次舞台自动把候场切精简卡；手动切档优先，且不覆盖用户偏好 |
| 候场栏左/顶排布 | 主区宽度 ≥1080 时候场栏在左侧，否则在顶部；两种排布都可拖比例、可收起 |
| 拖拽编排 | 把官方左栏会话拖进舞台：落焦点区 = 替换焦点，落候场栏 = 加入候场；原焦点自动降为候场 |
| 键盘快捷键 | Ctrl+Alt 系（§5），经官方快捷键系统注册，可在 DSH 快捷键页改键 |
| 焦点/候场交换动效 | 基于 View Transitions；焦点↔候场、增删淘汰、候场栏收展都走命名元素 morph；支持减少动效 |
| 伴生浮窗 | 舞台模式下文件/文档等官方右栏 tab 以右侧独立浮窗打开：8 向边缘缩放、点击外部收起为右缘标签、标签整堆拖动、收起后再点链接可直接展开对应浮窗 |
| 浏览器伴生窗 | 浏览器 tab 仅在桌面 profile 可打开（依赖目标 profile 的 `ui-sidebar-browser` bundle）；web/隔离 profile 按设计降级 |
| 双语与无障碍 | 跟随 DSH 语言（中文/英文），即时切换不重挂载窗口；键盘可达、ARIA 标注、reduced-motion |

**设计边界**：插件不改 DSH 本体、不 fork、不 patch 官方 bundle；舞台只接管官方会话主区，官方左栏保持原样，官方右栏仍可使用。卸载后界面回到官方单会话形态。

**已知限制（如实披露）**：

- 为获得官方没有的能力，插件依赖若干**非公开扩展点**：包装官方 `sidebarRight.openResource/openTab`；对官方浮窗 DOM 注入属性/样式并自绘右缘标签层；沿 React fiber 读取官方 FloatLayer 的 `intents.resizeFloat`；只读官方 localStorage 键。DSH rc 升级时需按[兼容性说明](compatibility.md)做契约 diff；能力自检失败时自动退回官方行为。
- 浮窗缩放**没有键盘等价路径**（与官方右下角缩放一致）；收起标签拖动只改纵向位置、始终贴右缘。
- **浏览器 tab 仅桌面 profile**；web/隔离 profile 不支持，这是官方 profile 门控，不是插件缺陷。
- **极简档**（连续低帧率/内存超限时把舞台收为状态条）为 v1.1 候选，**当前未实现**；当前自动降级最低到精简卡。
- 点击换焦的慢速占位动效期间，焦点窗先显示占位骨架；真实聊天体在动画期间挂载完成，视觉上在动画结束前后才出现。

## 2. 安装

### 2.1 前置检查

- **DSH 版本**：必须在支持范围内（见页首），可用 `<DSH 安装目录>\resources\runtime\cli\bin\dsh.cmd --version` 查看。超出范围不承诺可用；把插件装到不支持的 DSH 上可能因官方契约差异而降级或失效。
- **profile 区分**：桌面 App 使用 `desktop` profile，由 App 独占管理；隔离 profile 用于开发与回归，二者插件互不影响，但**会话目录共用**（隔离 profile 只隔离插件配置/依赖，不是会话数据隔离）。
- **插件形态**：客户端插件包（宿主半 `index.js` + 浏览器半 `client.js`），通过 DSH 的插件安装链路装入 profile 后，由 profile 的 bundle 列表激活。

### 2.2 桌面 App（推荐路径）

1. 打开 DSH App 的 **Plugins（插件）页**，安装 `dsh-onestep`（有社区市场入口时同理）。
2. 在插件页启用；**首次安装后重启 DSH**（插件在启动时装载）。
3. 卸载、回滚也走同一页面，操作后重启生效。

> 桌面 profile 由 Electron 应用独占管理。**不要用 CLI 给桌面 profile 安装插件**：对 `desktop` profile 的 CLI 只有只读 `list` 可用，`add`/启动会被拒绝（这是 DSH 的既有边界）。

### 2.3 隔离 profile（开发/回归，不碰桌面 App）

需要本地仓库或已发布的插件包。Windows 下 CLI 位于 `<DSH 安装目录>\resources\runtime\cli\bin\dsh.cmd`；其它平台使用对应的 `dsh` 可执行文件，路径以实际安装为准。

```powershell
# 1) 首次：从内置 web 模板创建隔离 profile 并启动（示例端口，可自行更换）
#    注意：--from-default-profile 会重置该 profile 的插件安装；之后启动不要再带它
& "<DSH 安装目录>\resources\runtime\cli\bin\dsh.cmd" `
  onestep-dev --from-default-profile web --no-open --port 4650

# 2) 另开一个终端：把本仓库作为插件装入该 profile
& "<DSH 安装目录>\resources\runtime\cli\bin\dsh.cmd" `
  plugin --profile onestep-dev add "<本仓库目录>"

# 3) 回到第 1 个终端，停止实例（Ctrl+C），再重新启动（不带 --from-default-profile）
& "<DSH 安装目录>\resources\runtime\cli\bin\dsh.cmd" `
  onestep-dev --no-open --port 4650
```

- `plugin add` 会自动把包名写进该 profile 的 `dsh.profile.bundles`；**bundles 才是激活开关**，只有依赖不会加载，无需手改配置。
- 启动输出会打印访问地址；地址里带一次性访问凭据，**每次重启都会变化**，不要外传或截图。
- 开发内环：改 `client.js` 后刷新页面即生效（client-hmr）；改宿主半 `index.js` 或首次安装需要重启实例。
- 安装/卸载以「停实例 → 变更 → 启动 → 验证」的确定性顺序为准，不要依赖运行期热挂载。

### 2.4 从 npm 安装（已发布 1.0.0）

插件发布到 npm 后，包名为 `dsh-onestep`，隔离 profile 可直接按包名安装：

```powershell
& "<DSH 安装目录>\resources\runtime\cli\bin\dsh.cmd" `
  plugin --profile <隔离 profile> add dsh-onestep@1.0.0
```

安装后重启实例；桌面端仍走 App 的 Plugins 页（§2.2）。离线或需要改代码验证时，用 §2.3 的目录安装路径。

### 2.5 更新与版本核对

| 场景 | 做法 |
|---|---|
| 桌面 App 更新 | 在 Plugins 页安装新版本，重启 DSH；回滚同理 |
| 隔离 profile 更新 | 重新 `plugin add` 目标版本（或更新源码目录）后重启实例 |
| 升级/降级数据 | 舞台设置存在浏览器 localStorage，升级保留；降级对未知字段容忍，不阻塞加载 |
| 核对当前版本 | 插件加载后，在页面 Console 查看 `window.__ONESTEP__.version`；npm 包版本见 `package.json` |

> 从源码目录安装（`<本仓库目录>`）时，profile 里是链接依赖：改源码后按 §2.3 的重启规则生效。tarball 形态安装会拷贝包内容，卸载后无包目录残留。

## 3. 第一次进入舞台

任选一种入口：

| 入口 | 操作 |
|---|---|
| 左栏会话行 | 鼠标悬停会话行，点出现的 **「＋」加入舞台** 按钮：该会话进入候场并立即挂载舞台 |
| 会话头按钮 | 点会话头的 **「Onestep 舞台」** 按钮，打开选择浮层；勾选最多 12 个候场会话 → **进入舞台（N）**。Esc 或「取消」关闭 |
| 快捷键 | `Ctrl+Alt+S`：候场为空时打开选择浮层；已有候场时退出舞台 |
| 拖拽 | 普通模式下把官方左栏会话拖到会话区，落点 HUD 显示 **「加入焦点对话」/「加入非焦点对话」**，按落点决定替换焦点还是加入候场 |

进入后你会看到：

- **焦点窗**：当前主绑定会话，占会话主区；打开的就是官方聊天体与 composer。
- **候场栏**：候场会话卡片（√2:1），主区宽度 ≥1080 在左侧、<1080 在顶部；不覆盖官方左栏。
- **数量与滚动**：候场上限 12，超过可视容量时固定卡尺寸并滚动（滚轮、候场栏底部翻页按钮）；滚出视口的卡自动降为精简卡。
- **自动退出**：候场清空、或关闭最后一个窗口即退出舞台；主区窄于 760px 会提示「窗口过窄，已回到单会话」并退出（右栏展开挤压主区时先进入 compact：隐藏候场栏、单窗保活，主区窄于 480px 才退出）。

退出舞台的方式：`Ctrl+Alt+S`、焦点窗「…」菜单里的 **退出舞台**、关闭最后一个窗口。退出后候场 roster 保留在本地设置中，下次进入舞台会恢复（舞台持久化默认开启，见 §6）。

## 4. 日常操作

### 4.1 切换焦点

| 方式 | 说明 |
|---|---|
| 点击候场卡 | 把该候场提升为焦点；原焦点降为候场 |
| 点击官方左栏会话行 | 直接替换舞台焦点；原焦点降为候场 |
| `Ctrl+Alt+1` | 回到焦点会话输入框 |
| `Ctrl+Alt+2…9` | 提升第 1…8 个候场（键盘只覆盖到 Digit 9；第 9 个起滚动后点击） |
| `Ctrl+Alt+←/→` | 在焦点与候场之间循环切换 |

> 候场顺序：新加入的候场排在候场栏前面；候场满 12 后加入第 13 个会淘汰最久未用（LRU）的候场，并保留其会话。

### 4.2 新增候场

- **左栏会话行「＋」**：把该会话加入候场并进入舞台。
- **会话头「Onestep 舞台」选择浮层**：一次勾选多个候场（当前焦点不在列表内）。
- **快速新建**（§4.7）：新建的会话成为焦点，原焦点自动降为候场。
- **拖拽**（§4.4）：拖到候场栏或使用 HUD 的「加入非焦点对话」。

### 4.3 关闭、移出与撤销

| 操作 | 结果 |
|---|---|
| 焦点窗右下角触发区 → 关闭 | 焦点会话回到官方左栏（**不删除会话**）；自动把第一个候场提升为新焦点，焦点移到新焦点窗输入框 |
| 候场卡 hover → 右下控制点 | 该会话移出舞台（不删会话）；候场卡获得键盘焦点时也可按 `Delete`/`Backspace` |
| 关闭焦点但已无候场 | 退出舞台，回到官方单会话界面 |
| 关闭最后一个候场 | 退出舞台 |
| 撤销 | 关闭操作后 5 秒内：点 toast 的「撤销」，或 `Ctrl+Alt+Z`。焦点关闭有 toast 提示；候场关闭不弹 toast，但同样可撤销 |

### 4.4 拖拽编排

- **舞台内**：从官方左栏把会话拖到焦点区 = 替换焦点（旧焦点自动降为候场）；拖到候场栏 = 加入候场。
- **普通模式**：把左栏会话拖到会话区，按 HUD 落点选择「加入焦点对话」或「加入非焦点对话」；替换焦点时旧焦点自动降为候场。
- 满 12 时新加入会淘汰最久未用的候场；被淘汰的会话仍在官方左栏。

### 4.5 调整候场栏比例与收起

- **拖比例**：拖动候场栏与焦点窗之间的分隔条，**宽度不设固定上限**（左侧栏最小 200px、顶部栏最小 108px；最多可拖到焦点窗仍剩 480×320 的位置）。聚焦分隔条后可用键盘：`←/→`（左侧栏）或 `↑/↓`（顶部栏）调整 8px，`Shift` 24px，`Home` 到最小、`End` 到当前舞台最大可用。比例持久化；舞台变窄时自动收窄。
- **收起候场栏**：点候场栏的收起手柄（左侧栏在左下、顶部栏在右上）。收起后焦点窗占满、**不退出舞台**，保留展开手柄；键盘聚焦手柄后 Enter/Space 切换，`aria-expanded` 表达状态。方向按主区宽度自动选择（<1080 顶部），暂不提供手动切换。

### 4.6 候选预览档与自动精简

- **手动切档**：焦点窗「…」菜单 →「切换为精简候场 / 切换为静态快照候场」。选择持久化，且本次舞台会话内优先于自动判定。
- **自动精简（lite）**：4 窗（1 焦点 + 3 候场）且进入首帧 >900ms、主线程长任务累计 >400ms、或内存增量 >200MB 时，本次舞台自动把候场切为精简卡；焦点窗保持官方实时内容。自动降级**不写入用户偏好**（下次启动仍按你保存的档位），本舞台会话内不再覆盖手动选择。
- **静态快照的抓取**：每张候场卡在后台串行抓取一次官方画面（一次一张、抓取完成前显示精简卡占位），之后只显示静态快照；只有会话状态/标题变化时才重拍（运行中的流式内容不会实时刷新）。滚动、拖宽、悬停期间不再挂载官方内容。
- **极简档未实现**：连续低帧率/内存超限时「收成状态条」的方案属 v1.1 候选，当前不会触发。

### 4.7 快速新建

| 操作 | 说明 |
|---|---|
| 打开 | 焦点窗底部热区 hover 滑出快速条；或点焦点窗右上「＋」；或 `Ctrl+Alt+Shift+N` |
| 选工作区 | 快速条左侧工作区 chip 可切换目标工作区 |
| 创建 | 输入内容后 `Enter`（或点「创建」）：创建新会话并顶替焦点，原焦点降为候场；输入文本成为新会话的**草稿**，不自动发送 |
| 收起 | `Esc` 两段式：有文本先清空，再按收起；鼠标移开 400ms 自动隐藏，草稿保留 |
| 状态 | 创建中显示「创建中…」，失败显示「创建失败，请重试」 |

### 4.8 窗口级状态反馈

- 每个窗口有状态点与状态文案：运行中、等待批准、等待回答、计划待确认、已完成未读、空闲、新会话。
- 候场会话**完成**：卡片边框闪烁（2×600ms）。
- 候场会话**需要你处理**（批准/回答/计划确认）：卡片上弹出琥珀色气泡，点击气泡直接提升为焦点。
- 焦点切换、增删与候场栏收展有 View Transitions 动效；开启「减少动效」后全部关闭。

### 4.9 伴生浮窗（官方右栏的舞台形态）

舞台模式下，点在会话里打开文件/文档/浏览器/终端等官方右栏 tab 的内容，默认在屏幕右侧以**独立浮窗**打开，不挤窄焦点窗；同一内容再次打开只聚焦已有窗。

**开关与形态**

- 焦点窗的 **⇥** 按钮 = 伴生窗开/收：有可见浮窗时全部收起；有收起标签时逐个恢复；没有任何浮窗时打开一个 guide 浮窗。
- 焦点窗「…」菜单：**伴生窗：左右分屏**（把浮窗收回官方右栏）/ **伴生窗：恢复浮动**、**转回浮窗**（把收回右栏的 tab 重新变成浮窗）、**打开官方右栏**。
- 浮窗形态按会话记忆；非舞台模式或形态为左右分屏时，行为就是官方右栏。

**8 向边缘缩放**

- 浮动形态下每个浮窗有 8 个透明把手：左/右/上/下边 + 四角（边 6px、角 12px 命中带）。
- 拖动把手实时预览，松手提交一次官方 resize（可撤销、官方持久化、刷新后尺寸恢复）；`Esc` 取消；点一下边缘（无位移）不提交。
- 最小尺寸 220×140（与官方同值）；西/北侧缩放时对边固定，东/南侧受视口限制。
- 官方右下角缩放仍可用；**缩放没有键盘等价路径**；左右分屏形态不注入把手。
- **再次点击已打开的浮窗**：对应浮窗已展开时，点击链接不会重复打开，而是高亮闪烁两下并把该浮窗升到最上层（多个浮窗同时展开时）；减少动效设置下改为一次静态高亮。

**收起为右缘标签**

- 点击浮窗外的舞台区域 → 所有浮窗收起；右缘出现堆叠标签（图标 + 标题，键盘可达）。
- 点标签、或聚焦标签后按 Enter/Space，逐个恢复对应浮窗；收起状态不跨刷新（刷新会恢复全部浮窗）。
- 标签整堆可拖：在任意标签上**按下并上下移动 ≥4px** 即拖动整堆；松手在 10px 阈值内吸附到上/下沿或默认安全位置；只改纵向位置、标签层始终贴右缘；位置持久化。顶部手柄与 `↑↓`（`Shift` 24px、`Home/End`）仍可用。
- **点链接直接展开**：浮窗处于收起状态时，在焦点窗或会话内容里再次点击对应的文件/文档链接，会展开该浮窗并聚焦内容；其余收起标签不动。显式指定放置目标（`destination`/`paneId` 等）的打开按官方语义直通，不触发插件展开。

**槽位与上限**

- 浮窗按视口宽度分槽：约 1440 三槽、1280 两槽、窄屏一槽（视口 <900 或舞台 <760 时按一槽处理）。
- 满槽时打开新浮窗会收起最久未聚焦的浮窗以腾出槽位，并提示「浮窗已达上限，已收起最久未聚焦的浮窗」；内容不丢失。
- 浮窗不挤窄焦点窗；已有浮窗不会被插件动态重排（用户拖动由官方持久化）。

**已知边界**：只在「舞台模式 + 浮动形态」生效；不提供操作系统级独立窗口、跨设备/多标签页同步；浏览器 tab 仅桌面 profile（web/隔离 profile 按设计降级）。

### 4.10 键盘可达性

- 舞台区域、焦点窗、候场卡都有 ARIA 角色与标签；Tab 可在窗口 chrome、候场卡、分隔条、收起手柄、翻页按钮之间移动。
- 候场卡获得焦点后：Enter/Space 提升为焦点；`Delete`/`Backspace` 移出。
- 菜单打开时 `Esc` 关闭；选择浮层 `Esc` 取消；快速新建 `Esc` 两段式。
- 弹出/收起的收起标签是原生按钮，Enter/Space 恢复。

## 5. 快捷键

默认只注册 Windows 平台（`web:windows` / `desktop:windows`）；macOS/Linux 请在 DSH 的快捷键设置页自行绑定。所有键位都经官方快捷键系统注册，可在那里改键。

| 操作 | 默认键位（Windows） |
|---|---|
| 进入/退出舞台（候场为空时打开选择浮层） | `Ctrl+Alt+S` |
| 快速新建条 | `Ctrl+Alt+Shift+N` |
| 移出焦点会话（提升最近候场） | `Ctrl+Alt+Shift+W` |
| 撤销关闭 | `Ctrl+Alt+Z` |
| 回到焦点会话输入 | `Ctrl+Alt+1` |
| 提升第 1…8 个候场 | `Ctrl+Alt+2…9` |
| 焦点循环 | `Ctrl+Alt+←/→` |
| 候场卡键盘操作 | 标题按钮 Enter/Space 提升；右下控制点 Delete 移出 |
| 收起/展开候场栏 | 聚焦收起手柄后 Enter/Space |
| 调整候场栏比例 | 聚焦分隔条后方向键（Shift 24px、Home 最小、End 当前最大可用；无固定上限） |

> 官方保留组合键与输入法可能冲突，插件已避让 `Ctrl+Alt+W`（改用 `+Shift`）；如遇冲突请在 DSH 快捷键页改绑。

## 6. 设置项与存储

| 设置 | 入口 | 取值/默认 | 说明 |
|---|---|---|---|
| 候场预览档 | 焦点窗「…」菜单 | 静态快照（默认）/ 精简卡 | 手动切档后本次舞台优先，且持久化 |
| 动效 | 焦点窗「…」菜单 | 跟随系统（默认）/ 减少动效 | 减少动效时 VT 与动画全部关闭；系统 `prefers-reduced-motion` 同样生效 |
| 伴生窗形态 | 焦点窗「…」菜单 | 浮动（默认）/ 左右分屏 | 按会话记忆；「转回浮窗」只对有收回项的会话显示 |
| 打开官方右栏 | 焦点窗「…」菜单 | — | 临时使用官方右栏形态 |
| 语言 | DSH 设置 → 通用 → 语言 | 跟随 DSH（zh/en） | 插件文案即时切换，不重挂载窗口 |
| 主题 | DSH 设置 → 通用 → 外观 | 跟随 DSH | 深浅色均适配 |
| 候场栏方向 | 自动 | 主区 ≥1080 左、<1080 顶 | 暂不提供手动切换；收起状态持久化 |
| 自动精简 | 内部策略，默认开 | 无 UI 开关 | 阈值见 `src/client/store.js` 的 `AUTO_LITE_LIMITS`；不覆盖手动档位 |
| 舞台持久化 | 内部状态，默认开 | 无 UI 入口 | 刷新/重启后恢复候场 roster 与布局；关闭后不恢复 roster |

**存储位置**（仅浏览器 localStorage，不含会话内容与凭据）：

| 键 | 内容 | 写入时机 |
|---|---|---|
| `dsh.onestep.v1` | 舞台 roster、候场栏方向/尺寸、收起态、预览档、动效偏好、自动精简与持久化开关 | 变化后 300ms 节流 |
| `dsh.onestep.companion.v1` | 浮窗形态、槽位映射、被收起的窗集合、已收回右栏的 tab、收起标签纵向位置 | 变化时 |
| 官方键（只读） | `dsh.sessions.current`（推断主绑定会话）、`dsh.sidebar-right.v1.*`（浮窗对账） | 插件只读，不写回 |

官方浮窗的矩形、tab、展开态由 DSH 自己按会话持久化，插件不覆盖。**重置设置**：打开页面开发者工具 Console，执行 `localStorage.removeItem('dsh.onestep.v1')` 后刷新；伴生窗异常时再加 `localStorage.removeItem('dsh.onestep.companion.v1')`。重置只影响插件设置，不影响会话。

## 7. 故障排查

### 7.1 先收集诊断信息

1. **Console 日志**：开发者工具 Console 里过滤 `[onestep]`，记录红色报错与 `host.apply` / `shortcut.register` / `companion.*` 等事件。
2. **探针全局**（页面同源可见）：`window.__ONESTEP__.version`（应为 `1.0.0`）、`window.__ONESTEP__.snapshot()`（舞台/窗口/状态快照）、`window.__ONESTEP__.log()`（事件日志）。
3. **可选探针面板**：Console 执行 `localStorage.setItem('dsh.onestep.probe','1')` 后刷新；面板出现即表示插件已加载（移除该键并刷新即关闭）。
4. **诊断开关**：URL 后加 hash `#onestep=no-locale,no-shortcuts,no-entries,no-overlay,no-sessions,no-main`，可逐个禁用 locale/快捷键/入口/浮层/会话订阅/接管，用于定位问题面。
5. **宿主半日志**：默认只写控制台；仅当配置 `probeLog` 或环境变量 `ONESTEP_P0_LOG` 时才写 JSONL 日志文件。

> 提交问题前请**脱敏**：快照与日志可能含会话标题/ID 采样，请删除或替换为占位符，不要附带访问凭据、账号信息或完整会话正文。

### 7.2 常见问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 左栏没有「＋」、会话头没有「Onestep 舞台」按钮 | 插件未装载，或当前 DSH 版本超出支持范围 | 确认 Plugins 页已安装并启用；隔离 profile 用 `plugin --profile <profile> list` 核对；**重启 DSH**；检查 DSH 版本 |
| 整个 DSH 页面白屏 / 提示 `Failed to load plugins` | bundle 加载失败会阻塞整页 boot（DSH boot 图契约） | 按 §7.3 卸载插件并重启；保留控制台报错 |
| 进入舞台后立刻提示「窗口过窄，已回到单会话」 | 会话主区 <760px（窗口太小或右栏占宽） | 收窄/收起右栏，或放大窗口；右栏展开时会先进入 compact 保活 |
| 点文件/文档链接后仍在右栏打开（没浮动） | 当前不是舞台模式、会话形态是左右分屏、或右栏已被手动展开（按设计尊重右栏） | 「…」菜单切「伴生窗：恢复浮动」；用 ⇥ 收起右栏后再点链接 |
| 浮窗没有出现 | 不是舞台模式 / 当前会话形态是左右分屏；视口过窄时只给一槽（可能被已有浮窗占满）；或能力自检失败（DSH 升级导致） | 先切换到舞台的浮动形态；放大窗口或收起已有浮窗；看 Console `[onestep]` 的 `wrap.install` / `companion.*` 日志；能力失败时插件自动回退官方右栏 |
| 收起后找不到浮窗 | 已收起到右缘标签（设计行为） | 点右缘标签恢复；或再点一次对应的文件/文档链接直接展开；刷新页面会恢复全部浮窗 |
| 浏览器 tab 打不开 | web/隔离 profile 的官方 profile 门控 | 改用桌面 profile（浏览器伴生窗仅桌面可用） |
| 候场卡没有画面 / 画面不更新 | 当前是精简卡、快照还在后台抓取，或该窗口渲染失败 | 「…」菜单切回静态快照候场；快照只在状态/标题变化时更新（不是实时画面）；若显示「内容渲染失败」，收集 Console 信息反馈 |
| 动效不出现 / 变硬切 | 已开启「减少动效」；或运行环境不支持 View Transitions | 「…」菜单切「动效：跟随系统」；不支持 VT 的环境会自动直切（功能不受影响） |
| 完成/待处理提示不出现 | 状态订阅异常 | 用 `window.__ONESTEP__.snapshot().statuses` 核对；反馈时附脱敏快照 |
| 舞台状态残留 / 布局异常 | localStorage 残留 | 刷新页面；退出再进舞台；必要时按 §6 重置 |
| 12 候场时卡顿 | 候场快照首次/状态变化时需挂载一次官方内容；精简卡开销最低 | 「…」菜单切精简候场；减少候场数量；收起不再看的浮窗；开启减少动效 |
| 卸载后界面仍异常 | 未重启 / 插件仍在 bundles | 重启 DSH；确认 profile 的 bundles 已移除插件名 |

### 7.3 整页 boot 失败的回退

bundle 加载失败会阻塞整页 boot。表现是：页面只显示 HARNESS 错误屏「Failed to load plugins」，控制台出现 `web boot: 1 entry did not activate` / `dsh-onestep: import failed` 等报错，官方会话界面不渲染、`window.__ONESTEP__` 不存在。这是**显式失败**（不会静默损坏数据），插件没有进入运行期。

回退步骤：

1. **桌面 App**：打开 App 的 Plugins 页，卸载 `dsh-onestep`，然后重启 DSH。
2. **隔离 profile**：停掉实例后执行
   ```powershell
   & "<DSH 安装目录>\resources\runtime\cli\bin\dsh.cmd" plugin --profile <隔离 profile> remove dsh-onestep
   ```
   再启动实例。
3. 重启后应恢复官方单会话界面；保留控制台报错用于反馈（可先按 §7.1 脱敏）。

### 7.4 彻底卸载

| 环境 | 步骤 |
|---|---|
| 桌面 App | Plugins 页卸载 → 重启 DSH → 确认恢复官方界面。插件从 profile 的 bundle 列表移除，不再加载 |
| 隔离 profile | 停实例 → `plugin --profile <隔离 profile> remove dsh-onestep` → 启动实例 → 确认 boot 条目回落、无 `window.__ONESTEP__` 与舞台 DOM |
| 清空设置（可选） | 在 Console 执行 `localStorage.removeItem('dsh.onestep.v1')` 与 `localStorage.removeItem('dsh.onestep.companion.v1')` 后刷新 |
| 彻底清理隔离 profile | 删除 DSH 用户数据目录下的 `profiles/<profile 名>`（`~/.dsh/profiles/…`）后重建。该目录只含插件配置/依赖，**不会删除 DSH 会话数据** |

已知残留：源码目录（`link`/`Junction`）形态安装时，卸载后 profile 的 `node_modules` 可能留下链接、`.pnpm` 基础设施与 `.plugin-manager/logs` 操作日志；它们不会被加载，不影响运行，重建 profile 可清空。tarball 形态安装卸载后无包目录残留。卸载**不会删除** DSH 会话、工作区文件或官方右栏状态。

## 8. 隐私与安全

- **无网络外发、无遥测**：插件不发起网络请求，不采集/上报使用数据（构建产物静态审计 fetch/XMLHttpRequest/WebSocket/sendBeacon 均为 0）。
- **仅本地 localStorage**：只写上述两个插件自有键，不含会话内容与凭据；只读官方 `dsh.sessions.current` 与 `dsh.sidebar-right.v1.*`。
- **不读凭据、不采集会话内容**：宿主半默认只在控制台记录 apply/dispose 探针事件；JSONL 日志需显式开启。
- **不改 DSH 本体**：不修改安装目录、不 patch 官方 bundle；卸载后不再加载。
- **非公开扩展点**已在 §1 如实披露；能力自检失败自动退回官方行为。
- **回环 `/plugins/**` 无鉴权**是 DSH 插件分发机制本身的暴露面（同机进程可读取插件 bundle）；不要把 DSH 实例暴露到不可信网络。完整口径见 [SECURITY.md](../SECURITY.md)。
- 漏洞请走 [SECURITY.md](../SECURITY.md) 的私密渠道，不要公开贴细节。
